## 2. 未実装の機能

| 機能 | 理由 |
|---|---|
| メルカリ・Yahoo!フリマの相場の自動取得 | 公式のマーケット検索APIが無い。規約に反するスクレイピング・アクセス制限回避は行わない |
| BOOKOFF店舗在庫の自動取得 | 店舗在庫を返す公開APIが確認できない |
| Amazon SP-APIによる中古価格取得 | 大口出品者アカウントとアプリ登録が必要 |
| Next.js・PostgreSQL・Prisma・Vitest への移行 | 開発環境がネットワーク遮断でパッケージを入手できなかった。移行手順は architecture.md と codex-handoff.md に記載 |
| 複数ユーザー（アカウント別のデータ） | 個人利用を想定。共有パスワードのみ |

## 3. データ取得上の制約

- BOOKOFFの在庫・価格は、店頭で確認した結果をCSVか手動で登録する必要がある。確認日時のない在庫は「在庫未確認」になる。
- フリマの売却済み価格は、利用者がアプリで「売り切れ」を確認して登録する。
- Keepaの取得は本番APIでの動作確認が未実施（応答を模したテストで確認）。Amazonの参考価格が税込定価と異なる商品がある。Keepaは2026年2月から中古価格を送料込みの定義に変更したとされる。
- 手数料の初期値（メルカリ10%、Yahoo!フリマ5%、Amazon本などは15%＋成約料）は2026年11月時点の公開情報。改定時は設定画面で変更する。
- 店舗マスタは2026-11-20時点の公式一覧の記録。自動では更新しない。
- アクセス用パスワードはHTTP（暗号化なし）の同一Wi-Fi内での利用を想定。インターネットに公開する場合はHTTPS化が必要。
